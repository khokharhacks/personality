01

Defense in Depth

The foundation domain: the core vocabulary of security (confidentiality, risk, vulnerability), physical protections, policy types, the full catalog of attack types you'll be tested on, and backup strategy.

1.1

Identify Core Security Principles

Every other topic in this guide is built on these definitions. Expect the exam to test whether you can tell these terms apart, not just define them individually.

The CIA Triad — the three goals every security control ultimately serves.

Threat

Anything with the potential to cause harm — a hacker, malware, a fire, a disgruntled employee. A threat is the "who or what."

Vulnerability

A weakness that could be exploited — unpatched software, a weak password policy, an unlocked server room. The vulnerability is the "open door."

Risk

The likelihood and impact of a threat actually exploiting a vulnerability. Risk only exists where a threat and a vulnerability meet.

Exam Tip

No threat + no vulnerability = no risk. If a question describes a weakness with nothing capable of exploiting it, the risk is low even if the vulnerability sounds scary.

Non-Repudiation

Proof that a specific person performed a specific action, so they can't later deny it — enabled by digital signatures, audit logs, and biometrics.

Principle of Least Privilege

Every user, process, and system should have only the minimum access needed to do its job — nothing more.

Attack Surface (including IoT)

The total sum of every point where an attacker could try to get in or extract data — open ports, user accounts, apps, APIs, and physical devices. IoT devices (cameras, thermostats, printers) expand the attack surface significantly because they're often shipped with weak default credentials and rarely get patched.

1.2

Define and Enforce Physical Security

Physical security is the outermost layer of defense in depth — if someone can walk up to the hardware, every technical control downstream is at risk.

Site Security

Controls at the building/facility level: fencing, security guards, badge readers, CCTV, lighting.

Computer Security

Protecting individual devices: cable locks, locked server racks/rooms, cases that alert on tampering.

Removable Devices & Drives

USB drives and external disks are an easy way to exfiltrate data or introduce malware — policies often disable USB ports or require encryption.

Mantraps

A small space with two interlocking doors — only one can ever be open at a time — used to stop tailgating/piggybacking into secure areas.

1.3

Identify Security Policy Types

Security controls fall into three families. This guide's opening diagram already showed you all three — here's the split that matters for the exam:

Administrative Controls

Policies, procedures, guidelines, and training — the "paperwork and people" layer. Examples: acceptable use policy, security awareness training, onboarding/offboarding checklists.

Technical Controls

Technology enforcing security automatically — the "systems" layer. Examples: firewalls, encryption, access control lists, antivirus, MFA.

Physical controls (locks, guards, mantraps — from 1.2) round out the full picture as the third classic control family, even though this exam objective names only administrative and technical.

1.4

Identify Attack Types

This is the densest objective on the exam — expect several questions built directly from this vocabulary list. Terms are grouped by category so you can spot patterns instead of memorizing a flat list.

Types of Vulnerabilities

Before the attacks themselves — know what kind of weakness they typically exploit:

Software

Bugs, unpatched code, or coding flaws (like unchecked input) that can be exploited.

Configuration

Insecure default settings, open ports, or misconfigured permissions left in place.

Human

Lack of training or awareness — people are tricked rather than systems being broken.

Physical

Unsecured hardware, facilities, or removable media that can be physically accessed.

Malware Types

Malware

Virus

Attaches to a legitimate file/program and needs a user action (opening it) to spread.

Polymorphic Virus

Changes its own code/signature each time it replicates, to evade signature-based antivirus detection.

Worm

Self-replicating and spreads across a network on its own — no host file or user action required.

Trojan Horse

Disguised as legitimate software; doesn't self-replicate — it relies on tricking the user into installing it.

Spyware

Secretly monitors and collects user activity (keystrokes, browsing) without consent.

Ransomware

Encrypts the victim's files/system and demands payment for the decryption key.

Adware

Automatically displays or downloads unwanted advertisements, often bundled with free software.

Rootkit

Gains and hides privileged (admin/root) access, often by modifying the OS at a deep level to stay invisible.

Backdoor

A hidden way to bypass normal authentication and regain access later, planted by an attacker or developer.

Keylogger (Software/Hardware)

Records every keystroke to capture passwords and sensitive data — can be a program or a small physical device on the keyboard cable.

Logic Bomb

Malicious code that lies dormant until triggered by a specific date or condition (e.g., "if my account is ever deactivated, delete these files").

Attack Techniques

Technique

Buffer Overflow

A program writes more data into memory than a buffer can hold, overwriting adjacent memory — can lead to crashes or code execution.

Zero-Day Attack

Exploits a vulnerability the vendor doesn't know about yet — there are "zero days" of patch protection available.

Denial-of-Service (DoS)

Floods a system or network with traffic/requests so legitimate users can't access it. Distributed (DDoS) uses many sources at once.

Cross-Site Scripting (XSS)

Injects malicious script into a trusted website so it runs in other users' browsers — often used to steal session cookies.

SQL Injection

Malicious SQL is inserted into an input field to manipulate or extract data from a backend database.

Brute Force Attack

Systematically tries every possible password or key combination until the correct one is found.

Man-in-the-Middle (MITM)

The attacker secretly sits between two parties, intercepting or altering communication that both sides believe is direct.

Man-in-the-Browser (MITB)

A MITM variant where malware infects the browser itself to alter transactions — commonly used against online banking.

Human-Based

Social Engineering

Manipulating people, not technology — phishing, pretexting, baiting, and tailgating all exploit trust and psychology rather than a technical flaw.

Full

Backs up everything, every time.

Restore: 1 backup set. Slowest backup, fastest restore.

Incremental

Backs up only what changed since the last backup (full or incremental).

Restore: last full + every incremental since. Fastest backup, slowest restore.

Differential

Backs up everything changed since the last full backup.

Restore: last full + latest differential only. A middle ground.
Exam Tip

Incremental backups grow smaller each day but restoring takes longer (more sets to apply). Differential backups grow larger each day but restoring is quicker (only two sets needed).

02

Operating System Security

How Windows and Linux protect the system itself — hardening, authentication, permissions, auditing, and encryption. This domain rewards knowing the exact Windows tool or feature name for each concept.

2.1

Identify Client and Server Protection

All of these are ways to shrink the attack surface introduced in 1.1 — fewer running services and enforced settings mean fewer doors left open.

Separation of Services

Running each service (web, database, mail) on its own system so compromising one doesn't hand over the rest.

Hardening

Disabling unnecessary services, ports, and default accounts, and applying secure configurations to reduce what an attacker can target.

Patch Management

The formal process of testing and deploying updates so known vulnerabilities get closed quickly and consistently.

Reducing the Attack Surface

The overall goal of the items on this list: fewer exposed services, ports, and features to attack.

Group Policy — gpupdate / gpresult

gpupdate forces an immediate refresh of Group Policy settings. gpresult shows which policies are actually being applied to a user or computer — the go-to troubleshooting command.

Secure Dynamic DNS Updates

Restricts DNS record updates to authenticated devices only, preventing an attacker from silently poisoning DNS entries.

User Account Control (UAC)

Prompts for permission or admin credentials before allowing any action that needs elevated privileges — even for admins logged in normally.

Keeping OS & Software Updated

The single most effective defense against known exploits — most breaches abuse vulnerabilities that already had a patch available.

Encrypting Offline Folders

Protects cached copies of network files stored locally (e.g., on a laptop), so a lost or stolen device doesn't expose that cached data.

Software Restriction Policies

Controls which applications are allowed to run at all, using a whitelist (only approved apps run) or blacklist (specific apps are blocked) approach.

2.2

Configure User Authentication

Authentication answers "are you who you say you are?" — these are the mechanisms and policies that enforce it.

Multifactor Authentication (MFA)

Requires two or more proof types: something you know (password), something you have (phone/token), something you are (fingerprint).

Password Policies

Enforced rules for complexity, minimum length, expiration, and history (so old passwords can't be immediately reused).

Remote Access

Securing connections (VPN, RDP) made from outside the physical network so authentication can't be bypassed off-site.

Secondary Sign-On — Run As / sudo

Performing an admin task without being fully logged in as admin. Windows: Run As. Linux/macOS: sudo. Both follow least privilege by keeping the daily account non-elevated.

Domain vs. Local Accounts

Domain accounts are centralized (e.g., Active Directory) and work across the network; local accounts exist only on one specific machine.

Kerberos

The default Windows domain authentication protocol — proves identity using time-limited tickets instead of ever sending a password across the network.

1. Client logs in → KDC issues a Ticket-Granting Ticket (TGT). 2. Client presents the TGT back to the KDC to request access → KDC issues a Service Ticket. 3. Client presents the Service Ticket to the App Server → access is granted, with the password never crossing the network.

2.3

Manage Permissions in Windows and Linux

The move-vs-copy behavior below is one of the most frequently tested — and misremembered — facts on the whole exam.

File & Folder Permissions

Windows NTFS uses Read, Write, Modify, and Full Control; Linux uses read/write/execute (rwx) for owner, group, and others.

Share Permissions

Apply only when a folder is accessed over the network. When share and NTFS permissions conflict, the most restrictive of the two always wins.

Inheritance

Subfolders and files automatically pick up the permissions of their parent folder unless inheritance is explicitly broken.

Take Ownership

A special permission letting an admin become the owner of a file/folder, granting full control regardless of the previous permissions — used to regain access to "orphaned" data.

Multiple Groups, Different Permissions

NTFS permissions from different groups are cumulative (the most permissive combination applies) — except an explicit Deny, which always overrides any Allow.

Delegation

Assigning specific administrative tasks (like resetting passwords for one OU) to a non-admin user, without granting them full admin rights.

Copy (same or different disk)

Always treated as a brand-new file.

Result: inherits the destination folder's permissions.

Move (different disk/partition)

Windows can't just relocate the pointer across partitions, so it's really a copy + delete.

Result: inherits the destination folder's permissions.

Move (same disk/partition) — the exception

NTFS just updates where the file is pointed to; the file itself is never rewritten.

Result: keeps its original permissions.
Exam Tip

Copy always inherits the destination. Move only keeps original permissions when staying on the same partition — moving across partitions behaves exactly like a copy.

2.4

Facilitate Non-Repudiation Using Audit Policies and Log Files

Auditing is what actually delivers on the non-repudiation principle from 1.1 — you can't prove who did something if you never logged it.

Types of Auditing

Success auditing (logs when an action succeeds), failure auditing (logs when it's denied), or both together.

What Can Be Audited

Logon/logoff events, object (file/folder) access, policy changes, privilege use, and account management actions.

Enabling Auditing

Configured through Group Policy or Local Security Policy on Windows; via auditd on Linux.

What to Audit for a Purpose

Match the audit type to the goal — e.g., audit failed logons to catch brute-force attempts, audit object access to watch a sensitive file.

Where to Save Audit Information

Windows Security log (viewed in Event Viewer); Linux syslog; often forwarded to a centralized SIEM for correlation.

Reviewing Log Files

Logs only have value if someone actually reviews them regularly to catch anomalies before they become incidents.

2.5

Demonstrate Knowledge of Encryption

Encryption protects confidentiality (from the CIA triad) by making data unreadable without the correct key.

Asymmetric (public/private key) encryption: anyone can encrypt with the recipient's public key, but only the matching private key — held only by the recipient — can decrypt it.

File & Folder Encryption (EFS)

Encrypts individual files/folders tied to a specific user's certificate — other users, even admins, can't open them without that certificate.

Encryption & Moving/Copying Files

Behaves like the permissions rules in 2.3 — copying an encrypted file to a location that doesn't support encryption (like a FAT32 drive) can silently decrypt it.

Drive Encryption

Encrypts an entire volume rather than individual files — protects all data on the disk even if the drive is removed and read elsewhere.

TPM (Trusted Platform Module)

A dedicated hardware chip that securely generates and stores encryption keys, tying full-disk encryption to the specific physical machine.

Secure Communication (Email, Text, Chat, Social Media)

Encrypting the content of messages in transit — e.g., PGP/S-MIME for email, end-to-end encryption for chat apps.

VPN Encryption Methods

Protocols like IPsec or SSL/TLS create an encrypted tunnel so traffic crossing a public network stays private.

Certificate Properties & Services

A digital certificate binds a public key to an identity and is signed by a trusted Certificate Authority (CA) — it carries an issuer, subject, validity period, and public key.

BitLocker

Windows' built-in full-disk encryption feature, most securely paired with a TPM chip to store its keys.

03

Network Device Security

The hardware and architecture layer — wireless protection, the devices that stand guard on a network, how networks get isolated from each other, and the protocols/ports every question on this domain assumes you already know cold.

3.1

Implement Wireless Security

Wireless encryption standards only ever get stronger over time — if a question asks which is "most secure," it's always the newest one listed.

Wireless security types, weakest to strongest. WPA3's SAE handshake specifically defeats offline dictionary attacks that worked against WPA2.

SSID

The broadcast name of a wireless network. Hiding it isn't real security — it's still discoverable with basic tools.

MAC Filtering

Allows only listed device hardware addresses to connect — weak on its own since MAC addresses can be spoofed.

Default Configuration (OOBE — Out-of-Box Experience)

The factory settings a device ships with, including default admin passwords. These are publicly documented, so changing them immediately on setup is a baseline security step.

3.2

Identify the Role of Network Protection Devices

A firewall's core purpose is to filter traffic between a trusted and untrusted network based on a defined rule set — everything below is a variation on that job.

Hardware vs. Software Firewall

Hardware: a dedicated appliance protecting an entire network. Software: runs on one host/OS, protecting just that device.

Network vs. Host Firewall

Network firewall guards a whole network segment at the perimeter; host-based firewall guards a single device.

Security Baselines

A defined, documented minimum set of security settings used as the benchmark systems are measured/audited against.

Content Filtering

Blocks access to specific content categories (e.g., social media, gambling) based on organizational policy.

Stateless Inspection

Examines each packet in isolation against static rules — fast, but has no memory of the larger conversation.

Stateful Inspection

Tracks the full context of active connections, so it understands whether traffic belongs to an already-established, legitimate session.

IDS Intrusion Detection System

Monitors traffic, detects malicious activity, and sends an alert. Passive — it doesn't touch the traffic itself.

IPS Intrusion Prevention System

Sits inline with traffic and can actively block a detected threat in real time, not just alert on it.

SIEM

Security Information and Event Manager — aggregates and correlates log/event data from across the whole environment for centralized monitoring and alerting.

Blacklisting vs. Whitelisting

Blacklisting blocks specific listed items and allows everything else. Whitelisting allows only listed items and blocks everything else — more restrictive and generally more secure.

3.3

Identify Network Isolation Methods

Each method below separates traffic or networks from each other for a different reason — know the reason, not just the acronym.

A DMZ (perimeter network) sits between two firewalls, hosting public-facing servers so the internet never touches the internal network directly.

Routing

Directing traffic between different networks or subnets using routers, based on destination address.

Honeynet

A decoy network built to attract attackers, letting defenders study attack techniques while diverting attention from real assets.

NAT / PAT

NAT translates private IPs to a public one for internet access. PAT lets many internal devices share one public IP by assigning each a different port.

VPN & IPsec

A VPN builds an encrypted tunnel over a public network; IPsec is a protocol suite that authenticates and encrypts each packet, commonly powering that tunnel.

Air Gap Network

Physically isolated from any unsecured network, including the internet — the strongest possible form of isolation.

DirectAccess

A Microsoft feature giving domain-joined Windows clients seamless, always-on connectivity back to the corporate network without a traditional VPN client.

VLAN

Logically segments one physical network into multiple separate broadcast domains — better organization and security without extra hardware.

3.4

Identify Protocol Security Concepts

Tunneling

Encapsulating one protocol's traffic inside another, often to move it securely across an untrusted network (the basis of most VPNs).

DNSSEC

Adds digital signatures to DNS responses so they can be validated as authentic, preventing DNS spoofing and cache poisoning.

Network Sniffing

Capturing and inspecting traffic on a network — legitimate for troubleshooting (tools like Wireshark), but a serious threat when done by an attacker to steal unencrypted data.

04

Secure Computing

The everyday-user layer: protecting email, browsers, and endpoints from the threats an average person actually encounters day to day.

4.1

Implement Email Protection

Spoofing, phishing, and pharming get mixed up constantly — they overlap, but each names a different part of the attack.

Spoofing

Forging the "from" address so a message appears to come from a trusted source. A technique, not an attack goal on its own.

Phishing

A fraudulent message — often using spoofing — that tricks the recipient into revealing sensitive info or installing malware, usually via a link.

Pharming

Redirects a user to a fake website (often via DNS poisoning) even when they type the correct URL — no deceptive email required.

Antispam

Filters unsolicited bulk email before it reaches the inbox, reducing exposure to phishing and malware attachments.

Client Protection

Hardening the email client itself — attachment scanning, disabling auto-preview of risky content, blocking external images by default.

User Training

The single most effective email defense: teaching people to recognize suspicious senders, mismatched links, and urgency-based pressure tactics before they click.

4.2

Manage Browser Security

Browser Settings

Security zones, pop-up blockers, and script permissions that control what a visited site is allowed to do.

Cache Management

Clearing cached files and cookies protects privacy and removes any malicious content that may have been cached.

Private Browsing

Prevents history, cookies, and cache from being saved locally after the session ends — but it does not hide activity from the network, ISP, or visited websites.

4.3

Install and Configure Anti-Malware and Antivirus Software

Installing / Uninstalling / Reinstalling

Only one real-time AV engine should run at a time — conflicting engines can disable each other's protection.

Updating

Signature definitions need constant updates; a fully installed but outdated AV product can miss brand-new threats entirely.

Remediation

The process of removing detected malware and repairing whatever damage or changes it made to the system.

Scheduling Scans

Quick scans check common infection points fast; full scans check the entire system and should run on a regular schedule.

Investigating Alerts

Every alert needs a judgment call — is it a true positive (real threat) or a false positive (legitimate file wrongly flagged) — before deciding how to act on it.
